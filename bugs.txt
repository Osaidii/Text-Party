WEBSOCKET AND NETWORKING

1. Error: listen() and _send() both call recv() on the same websocket, so they can steal each other's messages. A normal reply can be eaten by listen(), and _send() times out.
Solution: Use a single reader task that owns all recv() calls. It puts messages with a "status" key into a reply queue that _send() waits on, and treats messages with an "action" key as broadcasts. Guard requests with an asyncio.Lock. Delete listen() and listener().

2. Error: concurrent _send() calls (for example an update and a members request) can both see ws_connection == "" and open duplicate connections. The only cross-thread writes are the ws_connection = "" lines in the stop_party() and leave() workers.
Solution: Create an asyncio.Lock on the event loop and hold it while connecting or reusing ws_connection. Alternatively, confine ws_connection to the event-loop thread and never touch it from worker threads.

3. Error: leave(), stop_party() and the cleanup code just set ws_connection = "" without closing the socket, so the old connection and its reader stay alive.
Solution: Call await ws_connection.close() via run_coroutine_threadsafe before clearing the variable.

4. Error: when the connection drops, party_mode stays True, so later updates fail silently or reconnect without rejoining the party.
Solution: Write one disconnect(message) function that resets party_mode, conn and ws_connection, closes the socket and informs the user. Call it from the reader's finally block and from the update error paths.

5. Error: get_public_ip() can abort party setup. The default urllib User-Agent may be rejected, and any failure to reach api.ipify.org blocks create and join, even though the UI never shows the IP.
Solution: Remove the lookup and send an empty IP (adjust the server if needed). Otherwise, at least set a User-Agent header.

6. Error: the GUI freezes for up to 10 seconds after you pause typing for 500 ms in a party. The scheduled send() runs on the main thread, and send_request blocks on future.result(timeout=10).
Solution: Have the scheduled function start a daemon thread that does the request.


PARTY LOGIC

7. Error: remove() does nothing, because the worker is defined but never started. (Once started, its existing try/except already reports send errors.)
Solution: Add threading.Thread(target=worker, daemon=True).start() at the end of remove().

8. Error: a member leaving can destroy the party for everyone, because stop_party() and on_close always send "destroy". remove() also has no owner check on the client.
Solution: Track is_owner (True in start_party, False in join). The host sends "destroy", a member sends "leave", and Stop Party and Remove are refused for non-owners. Also confirm the server enforces ownership, since the client check alone can be bypassed.

9. Error (minor): party_mode is set to True before the server confirms, so during a failed create or join the app is wrongly treated as in a party (New/Open are blocked, on_close takes the party path). stop_party() already returns early when conn == "", so no "destroy" is sent.
Solution: Set party_mode = True only in the worker's success branch.

10. Error: join() clears the user's text before the join succeeds. It also prompts to save before checking party_mode, so a failed join leaves an empty file.
Solution: Check party_mode first. Clear the text and reset the file state only in the success branch.

11. Error: remote updates cause an infinite echo loop. Inserting received text fires <<Modified>>, which calls update_text and sends the text straight back.
Solution: Keep a last_synced string and return early in update_text if the current text equals it. Set it whenever you send or apply remote text. A plain boolean flag is unreliable because Tk may deliver <<Modified>> after the function returns. (Keep the edit_modified(False) reset: Tk only fires <<Modified>> when the flag goes from False to True, so the reset is required. With last_synced, the extra re-entry it causes is harmless.)

12. Error: applying a remote update wipes the cursor position, scroll position and undo history.
Solution: Write an apply_remote(new_text) function that saves the insert index and yview, turns undo off, replaces the text only if it differs, turns undo back on, restores both, and sets last_synced. Use it on join as well.

13. Error: late-binding lambdas in the receiver. The root.after lambdas capture data by reference, so a later message can overwrite it before the callback runs. The same applies to the delete and insert pair being scheduled as two separate callbacks.
Solution: Capture the value at schedule time, for example t = data.get("text", "") and then root.after(0, lambda t=t: apply_remote(t)).

14. Error: pending_update is never cleared. After the delayed send() runs, it still holds the old callback ID.
Solution: Set pending_update = "" at the start of send().

15. Error: a send can still run after leaving. leave() cancels pending_update, but if you type after clicking Leave and before the leave worker clears conn, a new send gets scheduled and can hit a closed socket.
Solution: Have send() re-check party_mode and conn when it executes.

16. Limitation: every update replaces the whole document, so simultaneous edits are lost, including your own keystrokes during the 500 ms delay.
Solution: Send and merge diffs (operational transform or a CRDT). This is a design change, not a quick fix.

17. Error: worker threads call root.after() directly, which raises RuntimeError or TclError if the main loop has already exited or the window is destroyed. This affects every worker (create, join, leave, stop, remove, members), not just see_members().
Solution: Add a closing flag and a safe_after(fn) helper that checks it and wraps root.after in try/except (RuntimeError, tk.TclError). Use it from all threads. Also check root.winfo_exists() inside show() in see_members().


FILE HANDLING

18. Error: encoding is inconsistent. askopenfile and asksaveasfile do not take an encoding argument, so askopenfile(..., encoding="utf-8") likely raises a TclError and Open may fail entirely. The other file operations use the platform default, which can corrupt non-ASCII text on Windows.
Solution: Use askopenfilename and asksaveasfilename, then call open(path, mode, encoding="utf-8") everywhere (open, save, save_as, is_file_saved, backups).

19. Error: save_file() continues to the backup code after the main save fails.
Solution: Return False immediately after the main save error.

20. Error: backups pile up. Each save renames the backup to a new timestamped name and never deletes the old ones, so the save folder grows without limit. (The rename-failure scenarios are speculative: the file is closed by "with", and a same-second rename targets the same path.)
Solution: Keep one backup path per file, write directly to it, and overwrite it (or prune old backups). If you keep renaming, use os.replace.

21. Error (minor): autosave() calls winfo_exists() and root.after() and could raise TclError during teardown.
Solution: Wrap the body in try/except tk.TclError, and cancel the scheduled callback in on_close.

22. Error: save prompt return values are wrong. save_file_popup returns True after "Yes" even if Save As was cancelled, and save_file returns None on success, so new/open/join/close can discard unsaved text.
Solution: Make save_file and save_as return True on success and False on failure or cancel, and use "return save_file()" in the True case.


ADDITIONAL ISSUES (not in the original list)

23. Error: server broadcasts other than "update_text" are ignored. If the host destroys the party or you are removed, the client stays in party_mode.
Solution: In the new reader task from item 1, handle those actions (for example destroy and removed) by calling disconnect(message).

24. Error: latent NameError. Several lambdas use {e} after an "except ... as e:" block, but Python deletes e when the block ends. These blocks are also dead code today, because send_request never raises and errors come back as status dicts.
Solution: Copy the message first (msg = str(e)) and use msg in the lambda, or remove the dead except blocks and handle status == "error" instead.

25. Error: IP privacy. The client sends its public IP, and "members" returns everyone's IPs, even though the UI never displays them.
Solution: Drop the IP on both client and server (see item 5).
